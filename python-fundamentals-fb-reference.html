VS Code workspace

Always open by workspace file — never by folder. This ensures the correct venv and Marimo path activate automatically.

⚠️ Always open by .code-workspace — opening by folder bypasses interpreter and Marimo path settings. The workspace file is authoritative.

What the workspace controls

SettingEffectWithout workspace
defaultInterpreterPath Points Pylance and the terminal to .venv Falls back to system Python — wrong completions, missing packages
activateEnvironment Auto-activates .venv in every integrated terminal Must run source .venv/bin/activate manually each time
defaultFormatter Ruff formats on save (not Black/Pylint) Falls back to whatever formatter is set globally — may reformat incorrectly
marimo.marimoPath VS Code Marimo extension uses project's pinned version Extension uses system Marimo or fails to launch

Marimo notebook deployment (Python writer pattern)

⚠️ Browser renders marimo.App, mo.md, app.run as hyperlinks — corrupts bash heredoc. Always use the Python writer pattern.
✓ Correct — Python writer
python3 << 'PYEOF'
import pathlib
pathlib.Path("notebooks/14-builtin-functions/file.py").write_text('''
import marimo
app = marimo.App()
...
''')
PYEOF
✗ Wrong — raw bash heredoc
# Links in the content corrupt the heredoc
cat > notebooks/file.py << EOF
import marimo
app = marimo.App()   # ← rendered as hyperlink → file corrupted
EOF

DAG conflict patterns

Marimo's reactive DAG requires all variable names to be unique across cells. These patterns resolve the conflicts.

Conflict scan summary
37
Clean — direct convert
123
Require manual fix

Pattern A — Numeric suffix (most common)

✗ Jupyter (conflict in Marimo)
x = 10          # cell 3
x = 'hello'    # cell 7  ← DAG conflict — x defined twice
✓ Marimo fix
x_1 = 10        # cell 3
x_2 = 'hello'  # cell 7 — unique names, no conflict

Pattern B — Loop variable uniqueness Critical discovery

⚠️ For loop variables leak out of loops into Marimo's DAG cell scope. The static scanner does NOT catch this. This is the most common hidden conflict.
✗ Wrong — both cells export 'r' and 'c'
# cell A
for r in range(len(m1)):
    for c in range(len(m1[r])): ...

# cell B — CONFLICT: r and c already defined by cell A
for r in range(len(m2)):
    for c in range(len(m2[r])): ...
✓ Correct — unique loop vars per cell
# cell A
for r1 in range(len(m1)):
    for c1 in range(len(m1[r1])): ...

# cell B — OK: r2/c2 are fresh names
for r2 in range(len(m2)):
    for c2 in range(len(m2[r2])): ...
Standard naming convention: r1/c1 · r2/c2 · r3/c3 · e1/e2/e3 · v1/v2/v3/v4

Pattern C — Semantic suffixes

✓ Use when teaching the same concept in different types
a_int   = 10        # teaching int
a_float = 10.5      # teaching float
a_str   = 'hello'  # teaching str

Pattern D — Class version suffixes

✓ Use when a class is progressively enhanced across cells
class VectorV1: ...   # initial implementation
class VectorV2: ...   # adds __repr__
class VectorV3: ...   # adds __add__

Lessons learned

Permanent record of hard-won migration knowledge. Do not relitigate.

L1
Loop var leak — scanner blind spot
For loop variables persist into Marimo cell scope. The static conflict scanner does not catch this. Must be caught by manual inspection or runtime error. Always use unique names per cell: r1/c1, r2/c2, e1/e2/e3.
L2
Python writer — never raw bash heredoc
Browser renders marimo.App, mo.md, and app.run as hyperlinks inside bash heredocs, corrupting the output file. Always deploy notebooks with python3 << 'PYEOF' pattern using pathlib.Path.write_text().
L3
Generator exhaustion
Generators are consumed on first iteration. When the same generator is demonstrated multiple times across cells, each demonstration needs a fresh variable: squares_1 through squares_4. Reusing the same name silently returns empty on the second cell.
L4
pyproject.toml — both settings required
Both [tool.uv] package = false and [tool.setuptools] packages = [] must be present. Either one missing causes uv pip install -e . to fail with a confusing error.
L5
datetime.utcnow() DeprecationWarning
Python 3.12 emits a DeprecationWarning for datetime.utcnow(). This is expected and non-fatal. Do not attempt to suppress it in the notebooks — it is Fred Baptiste's code and part of the teaching material.
